# v0.12.0 MCP Modernization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adopt the MCP 2025-11-25 capabilities (tasks, elicitation, structured outputs, OAuth 2.1 resource-server auth) and publish the server to the official MCP Registry.

**Architecture:** All server behavior lives in `laravel_mcp_companion.py` (FastMCP server + 26 tool closures delegating to pure `*_impl` functions in `mcp_tools.py`); TOON encoding lives in `toon_helpers.py`. Structured outputs are added *alongside* TOON via `ToolResult(content=TOON, structured_content=dict)`. Registry artifacts (`server.json`, Dockerfile label, GitHub Actions OIDC workflow) are additive.

**Tech Stack:** Python 3.12, FastMCP 3.4.5 (pinned `<4`) + `tasks` extra, pytest with in-memory `fastmcp.Client`, TOON, GitHub Actions (registry publish only; Harness stays the CI).

## Global Constraints

- FastMCP pin stays `>=3.4.5,<4`; the only dependency change is the added `tasks` extra (mirrored in `pyproject.toml` AND `requirements.txt`, then `uv lock`).
- No version bump: `pyproject.toml` stays `0.11.0`; changes go under `[Unreleased]` in CHANGELOG.md.
- Every tool keeps returning TOON text content; structured content is additive, never a replacement.
- Coverage gate: `--cov-fail-under=65` must keep passing; `pytest.ini` is the only pytest config (guard test enforces this — do not add pytest config to pyproject).
- Protocol-level tests use in-memory `Client(server)` (pattern: `tests/unit/test_tool_surface.py:13`); new ones live in `tests/protocol/`.
- Commit after each task; plain `git commit` (evening/weekend) or `git lc` (weekday 9–5 Toronto).
- Lint/type gates before final commit: `uv run ruff check .` and `uv run mypy --ignore-missing-imports .`.
