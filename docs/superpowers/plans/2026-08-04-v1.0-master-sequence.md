Implements `docs/superpowers/specs/2026-08-04-v1.0-reference-library-design.md`.
The spec spans six subsystems; each gets its own plan that produces working,
testable software on its own. Execute in order — later plans assume earlier
ones have merged.

Ordering rationale: Plan 1 is non-breaking cleanup everything else builds on.
Plan 2 rewrites the tool layer, so it must precede the curated refresh (Plan 3
targets the consolidated tools) and the release docs. Plan 4 is independent of
2–3. Plan 1's Task 6 is the only other work that edits `docs_updater.py`, so
once Plan 1 has merged, Plan 4 can run in parallel with 3 if desired. Plan 5 depends on 2 (entry point wraps the final surface). Plan 6
is last by definition.

Each plan is written after its predecessors land, so it can be grounded in the
actual post-change code rather than guesses about it.

## Plan 4 after v0.14.0

v0.14.0 (2026-11-12) came out of an audit of the nightly docs sync, and it
fixed a large part of what §5 of the spec lists. This section records what
shipped and what is left, checked against the code at the v0.14.0 tag, so
Plan 4 is written against what remains.

### Shipped in v0.14.0

| §5 item | What shipped |
|---------|--------------|
| mtime cache-validity bug | Package cache age is read from a stored `cached_at`, not file mtime. |
| Inertia fetcher | Reads the site's `llms.txt`, newest major only (v3, 53 pages). |
| Laracasts | The topic index is saved, 60 topics read from `/series`. It is an index of topics, not lesson content. |
| Envoyer and Vapor discovery | Forge, Vapor, Envoyer and Nova are all read from each site's `llms.txt` through `fetch_llms_index_docs`. Navigation discovery and the HTML scrape path are deleted. |
| Forge/Nova scrape junk | Gone with the HTML path. |
| Filament unpin | Follows the major named in Filament's own index: 5.x today, not the 4.x the spec names. |
| `success_rate` against expected content | Measured against the index's page count for the six index-driven sources, against the section list for Spatie, Livewire and Debugbar, and against discovered courses and lessons for Laravel Learn. |
| CI freshness check | `docs_updater.py --sync-report` exits 1 when a source fetched under 90% of its pages, has not synced in two days, or has no metadata. The nightly pipeline runs it, puts the report in its pull request, and fails after publishing what did sync. One budget covers every source. |
| Real exit codes | `--all-versions` no longer exits 1 when versions are already current, and the pipeline acts on that exit code and the report's. |
| Pruning | Index-driven sources and Laravel Learn remove pages the site dropped, after a complete sync only. |
| Updater dead code | `DocumentationAutoDiscovery`, its `discovery_rules` and the HTML conversion helpers are deleted (888 lines). |

Not in the spec, also done: `bootcamp.laravel.com` stopped resolving, so the
`laravel-bootcamp` source now holds the laravel.com/learn courses; CI had not
run since 2026-08-04 and is now a required check on `main`; the docs and
release pipelines email a Harness user group when a run fails.

### Still open for Plan 4

- **Blog and news extraction.** Titles only, no summaries or dates, and
  `success_rate` is hardcoded to 1.0 in `_fetch_blog_index`,
  `_fetch_news_index` and `_fetch_laracasts_metadata`. The sync report
  therefore cannot show these three as partly failed, only as stale.
- **Spatie version detection.** `/v6/`, `/v11/` and `/v9/` are still
  hardcoded in the package config. A major bump that 404s every section is
  now reported as degraded by the sync report, but the fetch still breaks.
- **New fetchers: Laravel Cloud, Nightwatch, Herd.** For a site that
  publishes an `llms.txt`, a new service is one entry in `laravel_services`.
  Check for the index before writing a scraper.
- **Livewire and Debugbar** still use hand-kept section lists and HTML
  scraping. The spec's mechanism preference applies to them too.
- **Per-source freshness at runtime.** The only freshness gauge in `/metrics`
  is the age of the core docs copy, and `/healthz` degrades on that alone. The
  spec asks for
  a per-source last-fetch timestamp and item count in `/metrics`, and a
  `/healthz` that degrades when any source passes its age budget.
- **Per-source age budgets.** The sync report uses two days for every source.
- **Pruning for the hand-listed sources.** Spatie, Livewire, Debugbar and the
  blog and news indexes never remove a page.
- **`--update` exit code.** `overall_success` in `docs_updater.py` is
  unchanged. The pipeline no longer reads it, so whether it still treats "no
  changes" as failure has not been re-checked.
- **Docs-cron trigger mirror.** `.harness/.../triggers/` holds the CI push
  and release tag triggers. `Docs_Update_Cron` is still only in Harness.
- **JSX dead code.** `_process_jsx_to_markdown` and `_clean_jsx_text` have no
  callers.

Found while shipping v0.14.0, and worth folding into Plan 4:

- The release pipeline pushes the `latest` image tag on every tag build,
  docs tags included. When a docs tag and a version tag build within minutes
  of each other, `latest` goes to whichever finishes last. On 2026-11-12 that
  left `latest` reporting 0.13.0 until the v0.14.0 build was rerun.
- The failure email has not been seen to arrive; no run has failed since it
  was configured.
- With CI running again, a nightly sync costs roughly 50 of the account's
  2,000 monthly Harness build credits. Running out is what stopped every
  pipeline from 2026-10-25 to 2026-10-31.
