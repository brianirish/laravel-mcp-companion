# v1.0 Master Plan Sequence

Implements `docs/superpowers/specs/2026-08-04-v1.0-reference-library-design.md`.
The spec spans six subsystems; each gets its own plan that produces working,
testable software on its own. Execute in order — later plans assume earlier
ones have merged.

| # | Plan | Spec sections | Status |
|---|------|---------------|--------|
| 1 | `2026-08-04-p1-foundation-hygiene.md` — dedup primitives, dead code, import-time I/O, coverage honesty, ignore gaps | §7 (minus tools/ split) | Written |
| 2 | p2-tool-surface — `tools/` package + registry, 26→12 consolidation, output schemas for all, zero-results-as-success, error schema, snapshot tests, search diversity + limit, need-mapping query expansion, non-core section-read fixes, instructions rewrite | §2, §3, §7 (tools/ split) | Not written |
| 3 | p3-curated-refresh — 2026 content refresh (Cloud, Nightwatch, Herd, Pest, Volt, Filament, …), legacy demotions, dead-slug repairs, CI curation audit | §4 | Not written |
| 4 | p4-pipeline — resurrection fixes (mtime cache bug, Inertia, Laracasts, blog/news, Envoyer/Vapor discovery, Forge/Nova junk, Filament 4, Spatie versions), new fetchers (Cloud, Nightwatch, Herd), per-source freshness observability, pruning, scheduler mirror, updater dead code (JSX pipeline, decorative discovery_rules, unwired quality scoring) | §5 | Not written |
| 5 | p5-distribution — vendored TOON encoder, pyproject build-system + entry point, PyPI publish, Docker multi-arch/non-root/HEALTHCHECK/multi-stage, single version source | §6 | Not written |
| 6 | p6-release — README/ROADMAP rewrite, API reference, 26→12 migration guide, LTS + breaking-change policy, RC gating checklist | §1, §8 | Not written |

Ordering rationale: Plan 1 is non-breaking cleanup everything else builds on.
Plan 2 rewrites the tool layer, so it must precede the curated refresh (Plan 3
targets the consolidated tools) and the release docs. Plan 4 is independent of
2–3 but shares docs_updater with nothing else, so it can run in parallel with
3 if desired. Plan 5 depends on 2 (entry point wraps the final surface). Plan 6
is last by definition.

Each plan is written after its predecessors land, so it can be grounded in the
actual post-change code rather than guesses about it.
