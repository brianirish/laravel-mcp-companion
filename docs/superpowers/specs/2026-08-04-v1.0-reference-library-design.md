# v1.0 Design: The Laravel Reference Library

**Date:** 2026-08-04
**Status:** Approved
**Supersedes:** the v1.0.0 section of ROADMAP.md as written

## Why this document exists

A four-angle audit (product surface, curated-content currency, code health,
aggregation pipeline) compared the codebase against the project's stated
spirit — "a documentation aggregator and navigator for junior and
intermediate Laravel developers." The delta was not missing roadmap items.
It was that most of what makes the project distinctive on paper does not
currently work, while the part that works is not what the paper says the
project is:

- The real product in practice is two tools — `search_laravel_docs` +
  `read_laravel_doc_section` — and they are genuinely excellent: a Laravel
  answer in two calls at ~3K tokens instead of ~34K, current through 13.x.
- The curated layer (package catalog, learning paths, difficulty maps,
  need-mappings) was written once and never revised. Laravel Cloud,
  Nightwatch, Herd, Pest, Volt, and Boost appear nowhere; Vapor and Envoyer
  get promotional entries; 23 of 108 need-mappings and the flagship
  `getting-started` path reference dead doc slugs; the finder cannot see
  three of the four corpora the server aggregates.
- The aggregation pipeline is quietly rotting: five of six community
  package fetchers had not actually run in over a year (mtime cache bug),
  Laracasts has never produced a file, Envoyer/Vapor discovery is dead,
  junk files are served (`sitemap.xml.md`, CSS-as-markdown, double-`.md`),
  and every failure mode reports `success_rate: 1.0`. No artifact anywhere
  answers "which fetchers produced fresh content today."
- A v1.0 freeze today would freeze contracts the project doesn't own
  (fastmcp's `search_tools`/`call_tool` schemas), shapes that aren't
  defined (21 of 26 tools have no output schema), and claims that aren't
  true. The project is not pip-installable and structurally cannot be
  (git-URL dependency). The only three external bug reports in the
  project's 16-month life were all install failures.

Competitive reality: Laravel Boost (first-party, bundled, project-aware,
hosted docs API) has won the "active development context" use case.
Context7 owns breadth. Companion's defensible territory is what neither
serves.

## Decisions (made 2026-08-04)

1. **Identity: reference library.** Bet on multi-version + offline +
   no-project contexts. Not the junior-dev learning navigator, not a Boost
   competitor.
2. **Curated layer: keep + CI-audit.** Not deleted, not left to rot: a
   one-time 2026 refresh plus a CI gate that makes staleness a build
   failure.
3. **Aggregation sources: fix everything.** All 17 sources survive and get
   repaired, including the ones that never worked. Made survivable by
   non-negotiable observability.
4. **Tool surface: consolidate 26 → 12,** every survivor schema'd and
   snapshot-tested, one breaking release before the freeze.

## 1. Identity & positioning

Headline: **"Every Laravel version, the whole ecosystem, fully local."**

Companion is the reference library; Boost is the pair programmer. Three
claims nobody else makes:

- **Multi-version corpus** (6.x through latest) with cross-version
  comparison — the upgrade tool, the legacy-maintenance tool.
- **Fully offline / self-hosted** — corpus ships in the artifact,
  air-gapped capable, no vendor API, deterministic and auditable.
- **No-project contexts** — useful in Claude Desktop, chat, and learning
  settings where there is no composer.lock for Boost to read.

Changes: README comparison table rewritten to lead with these (and to stop
claiming differentiators the audit showed are broken); ROADMAP mission
statement drops "junior and intermediate developers" for "anyone
referencing Laravel — any version, any client, no project required."
Learning features remain as supporting cast, not the headline.

## 2. Tool surface: 26 → 12

One breaking release (v0.14.0) consolidates:

| v1.0 tool | Absorbs / notes |
|---|---|
| `search_laravel_docs` | Absorbs `search_external_laravel_docs`, `search_laravel_learning_resources` (already subsumed via `sources`). Exposes `limit`. Adds per-source diversity so one corpus cannot monopolize all results (today "assign roles" returns 5/5 Spatie hits, core `authorization.md` never appears). Drops legacy `include_external`. Gains a query-expansion layer over the need-mappings (see below). |
| `read_laravel_doc_section` | Fixes: section resolution for non-core corpora (anchors are empty and headings carry Mintlify zero-width markup, so search→read round-trips fail for services/packages today). |
| `read_laravel_doc_content` | Absorbs `get_doc_structure` as an `outline` mode (with code-fence-aware heading parsing). |
| `list_laravel_docs` | Absorbs `list_laravel_services`, `list_laravel_learning_resources`: one corpus enumerator with a `source` filter. |
| `laravel_docs_info` | Currency/metadata for **all** corpora, not just core. |
| `compare_laravel_versions` | Unchanged surface. |
| `update_laravel_docs` | Absorbs `update_external_laravel_docs`: one task-capable update tool with a `scope` argument. |
| `get_laravel_package` | Absorbs `get_laravel_package_info`, `get_laravel_package_categories`, `get_features_for_laravel_package`, `get_related_laravel_packages` — four projections of one 22-row table become one tool. |
| `recommend_laravel_packages` | Renamed from `get_laravel_package_recommendations`; use-case input. |
| `get_laravel_service_info` | Kept separate; services carry different metadata than packages. |
| `get_laravel_learning_path` | Absorbs `list_laravel_learning_paths` (empty argument already means list/elicit). |
| `browse_docs_by_category` | Absorbs `list_laravel_categories` and `get_laravel_content_by_difficulty`: category + difficulty filters on one browser. Fixes the count disagreement (categories reported keyword counts as doc counts). |

**Dropped:**

- `verify_laravel_feature` — a filename glob whose description instructs
  the model to trust it over its own knowledge, producing confident false
  negatives (`websockets` → `found: false` while Broadcasting and Reverb
  exist). Unsalvageable as designed.
- The 3 static prompts (`laravel-authentication-setup`,
  `find-payment-solution`, `laravel-forge-deployment`) — argument-less
  string constants referencing no real tool.
- `find_laravel_docs_for_need` as a standalone tool. The `NEED_MAPPINGS`
  data survives as a query-expansion/synonym layer inside
  `search_laravel_docs` — the mappings feed real ranked search instead of
  powering a parallel, weaker finder that can only see the core corpus.

**Resources:** the three templates (`laravel://`, `laravel-external://`,
`laravel-package://`) are kept and are part of the frozen contract.

**The frozen contract is the `--transform-mode none` surface:** 12 tool
names, input schemas, output schemas, 3 resource templates. `search` mode
remains the default delivery mechanism, but its `search_tools`/`call_tool`
meta-tools are documented as upstream-owned (fastmcp) and explicitly
outside the semver guarantee. Server instructions are rewritten per mode:
they must name the curated tools (reachability) and must stop recommending
the whole-file read that the tool descriptions themselves warn against.

## 3. Output contract

- Every tool returns TOON text **plus** `structuredContent` with a real
  output schema. Today only 5 of 26 do; the rest are undocumented strings.
- Snapshot tests pin every payload shape (inline-snapshot is already a dev
  dependency; it is currently unused against tool output). A change to any
  TOON header row or schema fails CI.
- **Zero results is a success** (`count: 0`), not an error object. Errors
  get a dedicated schema with `required` fields so clients can branch on
  failure without parsing English prose. This unblocks tightening the
  success schemas (`required` is currently empty everywhere because error
  and success share one shape).
- `toon_encode`'s silent fallback to Python `repr` on any exception is
  removed; encoding failures are real errors.
- The format is documented in a versioned API reference (docs/api.md), and
  the README's TOON example is corrected to match the real schema.

## 4. Curated layer: keep, refresh, gate

**One-time 2026 refresh:**

- Add to catalog/maps: Laravel Cloud, Nightwatch, Herd, Pest, Volt,
  Reverb, Pulse, Pennant, Folio, Filament (62 doc pages already on disk
  with no catalog entry), Sail, Pint, Prompts.
- Demote to legacy-flagged entries: Vapor, Envoyer, Homestead, Valet,
  Breeze, Jetstream (kept for the multi-version/legacy audience — the
  reference-library identity means old-stack users are real users — but
  flagged so recommendations prefer current tools).
- Correct dated prose: Octane (FrankenPHP is the default server),
  Socialite (drop Twitter, add current providers), Scout (Typesense,
  database driver), the "production-ready" path (Cloud, not Vapor),
  testing path (Pest).
- Repair every dead slug: 23 broken need-mappings, 9 difficulty-map stems
  with no backing file, 7 categories referencing dead slugs, the broken
  `getting-started` path.
- Map the unreachable corpus topics: `ai`, `ai-sdk`, `boost`, `mcp`,
  `folio`, `concurrency`, `mongodb`, `search`, `images`, `csrf`,
  `structure`, `urls`.

**CI curation audit (what makes "keep" sustainable):** a test suite that
fails the build when:

- any slug in any curated map does not resolve against the shipped corpus;
- any catalog documentation link no longer resolves (cheap HEAD check,
  network-marked);
- any catalog/map entry pins a package version older than what the
  fetchers fetch;
- a catalog entry exists without its corresponding `FEATURE_MAP` /
  `RELATED_PACKAGES` rows (today: 21 vs 22 inconsistency).

Staleness becomes a build failure instead of a discovery sixteen months
later.

## 5. Aggregation pipeline: fix everything, make death visible

**Resurrection fixes (bugs that silently stopped fetchers):**

- The mtime-based cache validity bug: fresh CI clones stamp every
  checked-in `cache.json` with mtime *now*, so the cache is always "valid"
  and five of six package fetchers have been skipped for a year. Validity
  must read the JSON timestamp.
- The Inertia llms.txt fetcher has never run in production (see above);
  the served corpus is the year-old JSX scrape. Verify it actually
  executes and commits.
- Laracasts: has never produced a file in the project's history. Rebuild
  against the SPA payload for real, or the freshness budget (below) fails
  the build until it works.
- Blog/news extractors currently emit titles with no summaries/dates and
  hardcode `success_rate: 1.0`; fix extraction and compute the rate.
- Envoyer discovery: returns 0 on every run since 2025-07-22 while still
  issuing per-candidate validation GETs daily. Vapor discovery: dead
  (Mintlify nav moved into JS). Fix or re-mechanize both.
- Forge/Nova scrape bugs: double-`.md` filenames, `sitemap.xml.md`,
  `llms.txt.md`, CSS-as-markdown (`/_next/` asset guard misses because the
  `/docs/` prefix is stripped first), junk pages ("Copy pageCopy page").
- Filament: unpin from 3.x → 4.x. Spatie: version detection instead of
  hardcoded `/v6/`, `/v11/`, `/v9/` (a major bump currently 404s every
  section while leaving `success_rate: 1.0` metadata in place).

**New fetchers:** Laravel Cloud, Nightwatch, Herd — the 2025-era
first-party surface, entirely absent today. Mechanism preference for all
fetcher work: llms.txt / markdown endpoints / raw files where the site
offers them (the durable pattern that fixed Inertia), HTML scraping only
where no alternative exists.

**Observability (non-negotiable, the condition on "fix everything"):**

- Per-source `last_successful_fetch` timestamp and item-count gauges in
  `/metrics`, alongside the existing core-docs age gauge.
- `/healthz` reports degraded when any source exceeds its age budget —
  today it watches only core Laravel docs, which update near-daily, so it
  reports `ok` even if every other fetcher returns zero bytes forever.
- A CI freshness check with per-source age budgets that fails the
  pipeline, so a dead fetcher is a red build within its budget window, not
  a year-later archaeology find.
- `success_rate` measured against expected/known content, not against
  whatever fallback list was substituted; discovery collapse (51 → 2
  sections) must not report 1.0.
- Real exit codes: the updater CLI's `overall_success` currently conflates
  "core had no changes" with failure, and the pipeline discards the status
  it captures. Fix both ends.

**Pruning:** generalize the Inertia-style prune — content no longer
produced by any fetcher is removed rather than served forever (half the
Vapor corpus on disk today is year-old orphans, including a filename the
current sanitizer would reject).

**Scheduler:** mirror the Harness docs-update cron trigger into git-backed
config so the single scheduler for the whole pipeline has a restore path
(per the repo's own trigger postmortem).

## 6. Distribution

The only thing external users ever filed issues about is installation.

- **pip-installable:** vendor a minimal TOON encoder (removes the
  PyPI-blocking `git+` dependency), add `[build-system]` and a
  `[project.scripts]` console entry point, restructure as an installable
  package, publish to PyPI. `pip install laravel-mcp-companion` and
  `uvx laravel-mcp-companion` become first-class install paths (corpus
  fetched on first run when not bundled).
- **Docker:** multi-arch build including ARM64 (the actual filed bug),
  non-root `USER`, `HEALTHCHECK` wired to `/healthz`, multi-stage build so
  the compiler toolchain doesn't ship, `.dockerignore` closed over caches,
  test dirs, and repo metadata currently baked into the image.
- `server.json` gains the PyPI package alongside the OCI one. The three
  hand-synced version strings collapse to one source of truth.

## 7. Internal restructure (prerequisite to freezing)

- Split the 831-line `configure_mcp_server` into a `tools/` package with a
  declarative registry, plus a **surface snapshot test** that enumerates
  the frozen contract (names + input schemas + output schemas). A freeze
  that nothing enforces is not a freeze.
- One containment primitive, one path/version parser, one file cache — the
  surviving cache is the `O_NOFOLLOW` variant; the `laravel://` resource
  path currently uses the one *without* the TOCTOU fix.
- Delete dead code: the "requires server context" shims, unused
  `format_search_results`/`format_learning_resource_search` (which pin a
  contradictory schema in tests), `search_laravel_docs_impl` (the security
  test currently exercises a path clients cannot reach), the orphaned JSX
  pipeline, the decorative `discovery_rules` config.
- Remove import-time network I/O: version resolution moves to explicit
  startup with a deterministic fallback; `import laravel_mcp_companion`
  must not block on GitHub for 30 seconds or let a network response decide
  every tool's default argument.
- Kill the `_server_config` module global (breaks multi-instance;
  resource handlers silently repoint).
- Coverage gate includes `doc_search.py`, `metrics.py`, `tool_schemas.py`
  — the BM25 engine behind the flagship tool is currently unmeasured while
  the README advertises 81%. The advertised number becomes true.
- Ignore/dockerignore gaps: `test_data/`, `test_docs/`.

## 8. Release path

1. **v0.14.0** — everything above. The one breaking release; release
   notes carry the full 26→12 mapping table as the migration guide.
2. **v1.0.0-rc** — freeze candidate: API reference, LTS +
   breaking-change policy docs, migration guide from 0.13.
3. **v1.0.0** — tagged when the curation audit, per-source freshness
   checks, and snapshot suite have run green through multiple daily
   pipeline cycles. ROADMAP's "Q3 2027" target is replaced by
   readiness-gated timing; this is months of work, not a year.

v1.0 success criteria (replacing ROADMAP's current list): the frozen
surface is enforced by tests; every source is within its freshness budget
or visibly degraded; `pip install` and `docker run` both work on amd64 and
arm64; the README contains no claim the codebase can't back.

## Not doing

Unchanged from ROADMAP's "What We're NOT Building", plus explicitly:
embeddings/semantic search, authoring original learning content, per-client
rate limiting (no identity without auth), web UI, and competing with Boost
on project-aware code-generation context.
